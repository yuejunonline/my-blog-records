这是一篇写给自己的 Hexo 博客日常更新与维护指南。当前博客已彻底理顺基于 **GitHub Actions（源码同步部署）** 与 **SSH 免密密钥** 的多端全自动流，后续在任何电脑上更新均需严格遵循以下规范。

---

## 💻 场景一：在【当前/常用】电脑上创作并更新

当你就在目前这台已经配置好环境的电脑上写文章时，只需执行以下标准三步：

### 1. 本地创作
在项目根目录下的 `source/_posts/` 文件夹中，新建或直接修改你的 `.md` 文章文件。确保文章最上方有完整的头信息（Front-matter）：
```yaml
---
title: 文章标题
date: 2026-07-19 23:00:00  # 检查日期，不要写成未来时间，否则会被 Hexo 隐藏
index_img: /img/xxx.jpg     # Fluid 主题首页卡片配图路径
banner_img: /img/xxx.jpg    # Fluid 主题文章顶部巨幕配图路径
---
```

### 2. 终端一键推送源码
写好并保存文件后，打开 Mac 终端（Terminal），确保路径在博客项目根目录（`my-blog-records`）下，直接依次运行这三条 Git 命令：
```bash
git add .
git commit -m "feat: 记录一篇新文章"
git push origin main
```
*注：由于已配置 SSH 密钥，此处回车后会秒速上传，绝不会再索要用户名或密码。*

### 3. 云端自动发布（无需任何人工干预）
终端提示推送成功后，即可直接关闭终端。GitHub Actions 机器人会在后台全自动接管编译与分发，**大约 1~2 分钟后**，直接强制刷新独立域名即可看到新内容。

## 🔄 场景二：换到【另一台/全新】电脑上写作

由于采用的是高级的“源码同步模式”，当你换到别的电脑（如公司电脑或笔记本）准备写作时，**必须多加一个“第 0 步”**以防版本冲突：

### 0. 写作前：强行拉取最新源码（核心）
在动手写任何新字之前，先打开那台电脑的终端，进入项目目录执行：
```bash
git pull origin main
```
此命令会将你之前在其他电脑上更新的所有文章、配置完美同步下来，确保两端数据绝对一致。

### 1. 开始创作与推送
拉取完毕后，重复执行【场景一】的步骤：**在 `_posts` 目录写稿 ➡️ 保存 ➡️ 运行三连 Git 命令推送**：
```bash
git add .
git commit -m "feat: 在另一台电脑更新"
git push origin main
```
云端机器人会再次自动打包，完美实现多端无缝无缝同步。

## ⚠️ 核心避坑防踩雷指南

* **忘掉 `hexo d` 命令**：当前博客已交由 GitHub 云端自动编译，**在本地严禁再次运行 `hexo deploy` 或 `hexo d`**，否则会用编译后的纯网页覆盖云端源码，导致后续自动部署彻底崩溃。
* **现代网页排版习惯**：写作时**首行彻底顶格，绝对不要敲空格缩进**。段落与段落之间直接敲**两次回车（留出一个完整空行）**，Hexo 会自动将其渲染为最舒适的现代网页段落块间距。
* **中英文混排规范**：在中文和英文（或数字、加粗 `**` 标签）之间，手动敲一个**半角空格**（例如：使用 Hexo 博客，而不是使用Hexo博客），能让整篇日记的排版视觉瞬间提升档次。
* **本地的环境搭建**：记得使用
```bash
git clone https://github.com/yuejunonline/my-blog-records.git myblog
```
